# Frontend Testing Strategy

## Goals

- Catch regressions in DSM computation logic (axis convention, SCC detection)
- Verify that the dependency-filtering UI renders the correct data from the GraphQL API
- Run fully in CI without a live backend (all requests intercepted by MSW)
- Fast feedback loop: the full suite runs in under 10 seconds

## Tech Stack

| Concern              | Tool                                                   |
| -------------------- | ------------------------------------------------------ |
| Test runner          | Vitest 4 (browser mode)                                |
| Browser              | Playwright provider, headless Chromium                 |
| React rendering      | `vitest-browser-react`                                 |
| Request interception | MSW 2 (`setupWorker`, `graphql.*`)                     |
| Fixture data         | Recorded JSON files from the deterministic fixture-app |

## Test Structure

```
src/
  components/dsm/
    dsmModel.test.ts        pure-function unit tests (DSM model logic)
    DsmCanvas.test.tsx      canvas-click → onSelectCell callback test
  testing/
    integration/
      dependency-filtering.test.tsx  DependencyDetailsPanel filter correctness
    fixtures/               recorded GraphQL fixture JSONs (do not edit by hand)
    msw/
      handlers.ts           MSW graphql.query handlers backed by fixture JSONs
      worker.ts             setupWorker export
    public/
      mockServiceWorker.js  generated by msw init (do not edit)
    render.tsx              renderWithQueryClient helper
    setup.ts                global beforeAll/afterAll MSW lifecycle
```

## Fixture Recording

Fixtures are recorded once against the live fixture-app backend and committed.
Re-record when the GraphQL schema or fixture-app data changes:

```bash
# Start fixture-app Neo4j store and MCP server first (see CLAUDE.md test-loop)
cd hierograph/hierograph-web
pnpm fixtures:record
```

The script (`scripts/record-fixtures.ts`) runs a BFS over the hierarchy and
records every operation + variable combination into
`src/testing/fixtures/<OperationName>.json`. Entries are deterministic
(sorted keys, sorted by variables); re-recording produces bit-identical output.

## DSM Axis Convention

`cell.row` is **horizontal (X)** and `cell.column` is **vertical (Y)** — the
opposite of standard matrix notation. `buildCellSelection(x, y)` maps:

- `sourceNodeId = labels[y].id` (= `labels[column]`)
- `targetNodeId = labels[x].id` (= `labels[row]`)

`DependencyMatrix.handleSelectCell` additionally flips source/target before
writing to `SelectionContext`, so the API sees:

- `cellSelection.sourceNodeId = labels[column]` (the package that depends)
- `cellSelection.targetNodeId = labels[row]` (the package being depended on)

Both the axis convention and the flip are documented in `dsmModel.test.ts`.

## Adding New Tests

1. **Pure logic** → add to `dsmModel.test.ts` or a sibling `*.test.ts`.
2. **Component with GraphQL** → use `renderWithQueryClient` from
   `@/testing/render`. MSW intercepts all requests automatically (setup in
   `src/testing/setup.ts`). If the component needs data not yet in the
   fixtures, re-record.
3. **New GraphQL operation** → add a `graphql.query` handler to
   `src/testing/msw/handlers.ts` and ensure the operation is recorded.

## Known Constraints

- **headless-tree hidden root**: `AsyncTree` passes `rootItemId` as the hidden
  container; `getItems()` returns only the root's _children_. Tests assert on
  children, not the root label.
- **Canvas coordinate system**: headless Chromium uses `devicePixelRatio=1`, so
  CSS pixels equal physical pixels and `setupCanvas` (which scales by DPR) is a
  no-op. Click coordinates in `DsmCanvas.test.tsx` are CSS pixel values.
- **optimizeDeps**: `@headless-tree/react` and several other packages must be
  listed in `vitest.config.ts → optimizeDeps.include` to avoid duplicate React
  instances in the Vite dev-server bundle.
